題目摘要

問題敘述： 三隻猴子在打字機上各自輸入了一段字串。給定目標字串與三隻猴子輸入的字串，請計算哪隻猴子的字串與目標字串的「最小編輯成本」最低。計費規則如下：

  • 新增 一個字元：成本 +2（允許在字串任意位置插入）
  • 刪除 一個字元：成本 +2
  • 取代 一個字元：成本 +3
  • 保留 字元完全相同：成本 +0

輸出規定： 輸出 N K，其中 N 為最小編輯距離的猴子編號（1、2 或 3），若距離平手則輸出編號最大者；K 為其最小編輯距離數值。

兩大範例精確演算與邏輯解析

【範例 1 深度解析】目標字串：abc

  • 猴子 1：bcd
    • 最優操作：保留 中間的 bc (成本 0)，刪除 尾端的 d (+2)，並在最前面 新增 a (+2)。
    • 總成本：2 + 2 = 4。
  • 猴子 2：cde
    • 最優操作：字串順序不可任意對調。最佳方式為保留相同的 c (成本 0)，刪除 猴子後續的 d, e (成本 2+2=4)，並在 c 前方插入目標所需的 a, b (成本 2+2=4)。
    • 總成本：4 + 4 = 8。
    • （若不保留 c 而把 3 個字元全部取代，成本為 3 × 3 = 9，故 DP 最優值為 8）。
  • 猴子 3：efg
    • 完全無重疊字元，3 個字元全數取代成本為 3 × 3 = 9。
  • 判定： 猴子 1 成本 4 最低 👉 輸出：1 4

【範例 2 深度解析】目標字串：abcd

  • 猴子 1：abcde → 刪除尾端 e，成本為 2。
  • 猴子 2：abc → 尾端補上 d，成本為 2。
  • 猴子 3：bcd → 前端補上 a，成本為 2。
  • 平手判定： 三隻猴子成本皆為 2。依規定平手時取編號最大者（3 ≥ 2 ≥ 1）👉 輸出：3 2

核心概念：編輯距離的「任意位置插入」vs「尾端操作」

💡 觀念澄清：為什麼 ab 變成 axb 成本是 2，而不是 5 或 6？
• 常見直覺盲點：誤以為輸入是單向的，必須「把 b 刪掉、插入 x、再把 b 打回來」（成本 6），或是「把 b 改成 x、再插入 b」（成本 5）。
• 編輯距離（Levenshtein Distance）真實定義：允許在字串的中間任意位置直接插入字元！因此 ab 只需要在 a 與 b 之間插入一個 x，a 與 b 兩者都免費保留，總成本僅為 2。

在二維陣列 DP[i][j] 中：

  • 列 (i)：代表目標字串的前 i 個字元。
  • 行 (j)：代表猴子字串的前 j 個字元。
  • 格子內的數值：代表將猴子前 j 個字元轉換成目標前 i 個字元所需的最小累積成本。
三向決策轉移規則：
1. 從左邊來 (j-1 → j)：DP[i][j-1] + 2 → 代表猴子字串執行「刪除」。
2. 從上面來 (i-1 → i)：DP[i-1][j] + 2 → 代表猴子字串執行「新增（插入）」。
3. 從左上方對角線來 (i-1, j-1 → i, j)：
• 若字元相同：DP[i-1][j-1] + 0 → 「保留」，免費對齊。
• 若字元不同：DP[i-1][j-1] + 3 → 執行「取代」。

【案例 1】目標：axb vs 猴子：ab 的逐格數值變化

DP[i][j] ∅ (j=0) 'a' (j=1) 'b' (j=2)
∅ (i=0) 0 2 (猴刪a) 4 (猴刪a,b)
'a' (i=1) 2 (猴補a) 0 (a與a對齊保留) 2 (配對a並刪b)
'x' (i=2) 4 (猴補a,x) 2 (在a後插入x) 3 (把b改成x)
'b' (i=3) 6 (全補) 4 (補x,b) 2 (最佳解)

👉 解讀 DP[3][2] = 2：目標第 3 字元 'b' 與猴子第 2 字元 'b' 相同，程式直接取斜上方 DP[2][1] 的數值 2（即目標 ax 與猴子 a 配對的成本），加上 0。這代表 b 完全沒有被動到，只有在中間插入了 x！

進階案例：字元倒置與跳字配對

目標字串：abc (L1=3) ； 猴子字串：bacd (L2=4)

這個例子猴子輸入了顛倒的 ba，且結尾多出了 d。我們觀察 DP 如何自動找出最划算的編輯策略：

DP[i][j] ∅ (j=0) 'b' (j=1) 'a' (j=2) 'c' (j=3) 'd' (j=4)
∅ (i=0) 0 2 4 6 8
'a' (i=1) 2 3 2 4 6
'b' (i=2) 4 2 4 5 7
'c' (i=3) 6 4 4 4 6

逐步決策軌跡追蹤：

  • DP[1][2] = 2（目標 a vs 猴子 ba）：
    猴子刪除開頭的 b（成本 2），並保留 a（成本 0），故成本為 2。
  • DP[2][2] = 4（目標 ab vs 猴子 ba）：
    編輯距離不允許直接無成本對調字元位置，只能「刪除 b、保留 a、再補插入 b」，成本為 2 + 0 + 2 = 4；或是兩字元皆替換（3+3=6）。DP 取最小值 4。
  • DP[3][3] = 4（目標 abc vs 猴子 bac）：
    兩者結尾皆為 'c'，直接承接 DP[2][2] + 0 = 4。
  • DP[3][4] = 6（終點：目標 abc vs 猴子 bacd）：
    猴子多了一個尾端字元 d，執行刪除，取左邊 DP[3][3] + 2 = 6。

👉 總結最優操作：刪除前端 b (+2)、保留 a (0)、插入 b (+2)、保留 c (0)、刪除 d (+2)，總成本為 6！

完整註解 C++ 實作程式碼

#include <bits/stdc++.h>
using namespace std;

#define infinity 999999

// DP[i][j] 代表：目標字串前 i 個字元，與猴子字串前 j 個字元的最小編輯成本
int DP[10005][10005];

int main()
{
    // s[0] 存目標字串，s[1]~s[3] 存三隻猴子打出來的字串
    char s[4][10001];
    for(int i = 0; i < 4; i++) {
        scanf("%s", s[i]);
    }
        
    int L1 = strlen(s[0]);   // 目標字串長度
    int win = 1;             // 優勝猴子編號，預設 1
    int mind = infinity;    // 紀錄全局最小成本，初始為無限大
    
    // 依序處理猴子 1、猴子 2、猴子 3
    for(int t = 1; t <= 3; t++)
    {
        int L2 = strlen(s[t]);  // 當前猴子的字串長度
        
        // 邊界初始化：空字串對齊長度為 i 的字串，成本就是連續新增或刪除 (每步 +2)
        for(int i = 0; i <= L1 || i <= L2; i++) {
            DP[i][0] = i * 2;
            DP[0][i] = i * 2;
        }
            
        // 動態規劃填表：i 代表目標字串索引 (1~L1)，j 代表猴子字串索引 (1~L2)
        for(int i = 1; i <= L1; i++)
        {
            for(int j = 1; j <= L2; j++)
            {
                if(s[0][i-1] == s[t][j-1]) {
                    // 情況 A：兩字元匹配相同，不需額外替換成本 (+0)
                    DP[i][j] = min(DP[i-1][j-1], min(DP[i][j-1] + 2, DP[i-1][j] + 2));
                } else {
                    // 情況 B：兩字元不同，可選擇：
                    // 1. 取代操作：斜角 DP[i-1][j-1] + 3
                    // 2. 插入/刪除：左方或上方 + 2
                    DP[i][j] = min(DP[i-1][j-1] + 3, min(DP[i][j-1] + 2, DP[i-1][j] + 2));
                }
            }
        }
        
        // 更新優勝者：若成本更小，或成本相同但編號更大 (<= 確保相同時取後者)
        if (DP[L1][L2] <= mind) {
            mind = DP[L1][L2];
            win = t;
        }
    }
    
    // 輸出最終優勝猴子編號及最小編輯距離
    printf("%d %d\n", win, mind);
    return 0;
}
