題目規格與子任務限制

問題敘述： 小明的軍團有 N 位士兵，第 i 位士兵的初始戰鬥力為 ai。小明準備至多 C 枚金幣為士兵升等。將等級 ai 升級至目標等級 U（若 ai < U）需花費 (U - ai)2 枚金幣；若 ai ≥ U 則不需花費。若要參加等級 U 的盃賽，所有士兵的戰鬥力都必須至少為 U。求小明最高可以參加多少等級的盃賽？

測資組別評分說明：

子任務 配分 士兵數 N 金幣數 C 初始戰力 ai 核心評測目的
第一組 10% N = 2 C = 1 1 ≤ ai ≤ 103 基礎特例測試（只能微調戰力差為 1 的士兵）
第二組 30% N ≤ 102 C ≤ 106 1 ≤ ai ≤ 103 中小型測資，驗證基礎模擬或線性掃描
第三組 60% 1 ≤ N ≤ 2 × 104 1 ≤ C ≤ 1014 1 ≤ ai ≤ 107 大數據範圍，需使用 O(N log(range)) 二分搜尋 與防溢位處理

演算法思維：二分搜尋答案 (Binary Search on Answer)

若我們設定目標等級為 U：

  • 花費函數具備「嚴格單調性 (Monotonicity)」： 當目標等級 U 越高，每位需要升等的士兵所需補足的差額 (U - ai) 越大，且平方和 ∑ max(0, U - ai)2 必然單調不減。
    👉 若等級 U 的金幣花費 ≤ C（可行），則任何等級 U' < U 也一定可行。
    👉 若等級 U 的金幣花費 > C（不可行），則任何等級 U' > U 也絕對不可能達成。
  • 搜尋區間設定 (Search Space)：
    • 下界 (L)： 設為 1（因 ai ≥ 1）。
    • 上界 (R)： 設為 2 × 107。極限情況為 N=1, a1 = 107, C = 1014，此時 (U - 107)2 ≤ 1014 ⟹ U ≤ 107 + 107 = 2 × 107。上界設為 20,000,000 恰好能完整覆蓋最大邊界。
  • 時間複雜度： 每次二分驗證遍歷 N 位士兵需 O(N)，搜尋範圍區間長度 R ≈ 2 × 107，二分次數約 log2(2 × 107) ≈ 25 次。總運算次數約 25 × 20000 ≈ 5 × 105 次，執行時間 < 0.05 秒，輕鬆通過 1.0 秒時限。

【範例 2 詳解】多士兵群體升等計算

輸入： 6 267 (6 位士兵, 267 枚金幣) ｜ 陣列： 25 39 36 17 20 39

在二分搜尋過程中，演算法會測試 U = 29 與 U = 30：

士兵編號 i 初始戰力 ai 升至 U = 29 之花費 升至 U = 30 之花費
第 1 位25(29 - 25)2 = 16(30 - 25)2 = 25
第 2 位39已達標 (0)已達標 (0)
第 3 位36已達標 (0)已達標 (0)
第 4 位17(29 - 17)2 = 144(30 - 17)2 = 169
第 5 位20(29 - 20)2 = 81(30 - 20)2 = 100
第 6 位39已達標 (0)已達標 (0)
總花費加總 16 + 144 + 81 = 251 25 + 169 + 100 = 278
比對金幣 C = 267 可行 (251 ≤ 267)，繼續向上搜尋 不可行 (278 > 267)，收斂上界

二分搜尋最終收斂並鎖定在最高可行等級 U = 29。

👉 輸出範例 2 結果： 29

【範例 3 詳解】極大數值與邊界極限推導

輸入： 1 100000000000000 (1014) ｜ 陣列： 10000000 (107)

數學推導過程：
  • 士兵數量僅有 1 位，戰力為 a1 = 10,000,000 = 107。
  • 金幣數量為 C = 100,000,000,000,000 = 1014。
  • 由花費公式 (U - a1)2 ≤ C，可直接代入計算： $(U - 107)2 ≤ 1014$ 兩邊取平方根： $U - 107 ≤ \sqrt{1014} = 107 ⟹ U ≤ 107 + 107 = 20,000,000$

此範例證明了設定搜尋上界 R = 20,000,000 的必要性，且展示金幣與花費計算必須使用 64 位元整數 (`long long`)，否則 1014 會超出 32 位元整數上限 (2 × 109) 導致溢位崩潰。

👉 輸出範例 3 結果： 20000000

參考解答 C++ 程式碼（100% 官方解答規格，繁體中文逐行詳解）

#include <cstdio>      // 引入標準 I/O 函式庫，使用快速的 scanf 與 printf

const int N = 100000 + 5;     // 定義陣列上限常數 (配合 N <= 20000 並保留彈性安全緩衝區)
typedef long long ll;         // 將 64 位元整數 long long 定義別名為 ll，防範金幣溢位

int n;                        // 士兵總數量 (1 <= n <= 2*104)
ll c, arr[N];                 // c: 金幣數量 (最高 1014); arr[i]: 各士兵戰鬥力 (最高 107)

// 驗證函數 can(level)：檢查能否將所有士兵提升至目標等級 level 且總花費不超過 c
int can(ll level)
{
    ll sum = 0;               // 累計升級所需的金幣總額
    for(int i = 0; i < n; ++i)
    {
        if(arr[i] < level)    // 只有當士兵戰力低於目標 level 時才需升級
        {
            // 累加升級花費：(目標等級 - 初始戰力)2
            sum += (level - arr[i]) * (level - arr[i]);
            
            // 剪枝優化 (Pruning)：若途中累計花費已超過總金幣數 c，提早失敗離開
            if(sum > c)
            {
                return 0;     // 回傳 0 表示金幣不足，無法達成
            }
        }
    }
    
    // 迴圈結束後若花費仍在預算範圍內，代表此等級可行
    if(sum <= c)
    {
        return 1;             // 回傳 1 表示可以達成
    }
    return 0;
}

int main()
{
    // x: 搜尋下界 (最低可能等級 1)
    // y: 搜尋上界 (由範例 3 推導之理論最大極限 20,000,000)
    // mid: 當前二分測試的中點等級
    // ans: 記錄歷次驗證成功中的最大等級
    ll x = 1, y = 20000000, mid, ans = 0;
    
    // 讀取士兵數量 n 與總金幣數 c
    scanf("%d%lld", &n, &c);
    
    // 依序讀取每位士兵的初始戰鬥力
    for(int i = 0; i < n; ++i)
    {
        scanf("%lld", &arr[i]);
    }
    
    // 開始執行二分搜尋答案 (Binary Search on Answer)
    while(x <= y)
    {
        mid = (x + y) / 2;    // 取目前區間中間值進行測試
        
        if(can(mid))          // 若 mid 等級可以達成
        {
            x = mid + 1;      // 嘗試挑戰更高的等級，將搜尋下界右移
            if(ans < mid) ans = mid;  // 更新當前找到的最佳有效等級答案
        }
        else                  // 若金幣不足無法達成等級 mid
        {
            y = mid - 1;      // 目標定太高了，降低搜尋上界往左縮小
        }
    }
    
    // 輸出小明軍隊最高能參加的盃賽等級
    printf("%lld\n", ans);
    
    return 0;                 // 程式正常結束
}
